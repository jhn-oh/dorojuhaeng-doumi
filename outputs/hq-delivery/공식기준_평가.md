## 서류와 사업성 보완

기존 신청서에서는 가칭 ‘면허연습노트’가 동승자의 답을 받아 오답을 확정하고, 7번에는 합성 화면을 소개했다. 공식 양식의 1~7번을 현재 앱명과 실제 동작으로 고쳤다. 참가자 인적 사항, 동의와 서명, 선택 숏폼은 본인이 작성할 수 있도록 보존했다. 효과나 시장 우위를 입증하지 않은 표현을 제거했다.

첫 달 활성 사용자는 **첫 주행을 마치고 복습까지 연 고유 인원**으로 잡는다. 안내 100명 × 차량·코스·연습 조건 충족 가정 25% × 첫 복습 가정 40% = **예상 10명**이다. 낮은 가정에서는 3명(10% × 30%), 높은 가정에서는 20명(40% × 50%)이다. 14일 관찰을 마친 첫 복습자 10명 중 4명이 다른 날짜의 별도 회차를 복습하는 것을 내부 목표로 삼는다. 같은 날 반복 시연은 포함하지 않는다. 실제 참여자 수와 재사용률은 아직 측정되지 않았다.

사용성 시험은 수험생·지도자 6쌍에게 동등한 연습 예시 두 개를 보여주고, 수기 메모와 차량 카드의 제시 순서를 교차한다. 1분 안에 **어느 구간에서 무엇을 다시 할지** 말할 수 있는지와 자료 부족을 성공·실패로 단정하는지를 기록한다. 6쌍 사용성 시험과 14일 재사용 코호트는 서로 다른 질문에 답한다. 이 자료를 갖춘 뒤에도 이용자 검증 전까지 사업성 등급은 2에 둔다.

## 개발 산출물과 제출 상태

기존 비공개 릴리스는 디버그 APK였고 지원서에는 현재 시연 경로가 없었다. 0.5.2는 서명된 release APK와 해당 소스 커밋을 하나의 ZIP으로 묶어, 저장소 공개가 어려울 때 주최 측이 허용하는 제출 방식에 맞췄다. ZIP 루트 README에 앱 소개, Pleos 이미지 버전·해상도, 실행 방법, APK 경로를 넣었다. SDK 키나 서명 자격증명은 묶음에 포함하지 않았다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

서명된 0.5.2의 APK를 새 Pleos 2.1.0 이미지에 설치해 동일 해시를 확인했다. 미체결 상태에서는 계기판 수업과 동일 점검으로의 복귀만 가능했다. 별도 신호 미지원 시험에서는 수동 점검 이후 D단·가상 18km/h에서 종료 동작이 숨겨졌고, 정차·P단에서 결과에 ‘비교할 구간 기록이 부족해요’와 좌우 각 ‘구간 기록 없음’이 표시됐다. **자료를 받지 못한 회차를 정상 깜빡이 사용이나 오답으로 계산하지 않았다.** 대표 이미지에서 체결 ON을 바꾸는 시험은 수행하지 못해 해당 경로는 단위 검사 근거다. 정상 신호 재연습의 근거는 버전을 표시한 기존 0.5.1의 2,250·2,324개 표본이다. [버전별 실행 검수](검수.md)

**출발 직전의 반례도 확인했다.** 중간 코드 16에서는 Vehicle 서비스를 재활성화해도 기존 앱 프로세스가 미확인 상태에 머물렀다. 최종 코드 17에서는 Vehicle 서비스가 꺼진 동안 운전자가 직접 확인해 코스 미리보기까지 간 후 서비스를 다시 켰다. 앱을 다시 열지 않고(PID 14194 유지) ‘이 코스로 시작’을 누르자, 복구된 미체결 신호가 이전 수동 확인을 무효화하고 벨트 1/3으로 돌려보냈다. 화면에는 새 미체결 상태와 재점검 안내가 표시됐고 다음·수동 확인 동작은 없었다.

개발 산출물의 가산점은 주최 측이 제출 수준과 열람 가능 여부에 따라 정한다. **비공개 릴리스만으로 심사위원 접근이나 가산점이 확보되지는 않는다.** 팀명(개인 출품 시 성명)에 맞춘 최종 파일명, 참가자 정보와 동의·서명, 심사위원이 받을 수 있는 다운로드 주소, 기한 내 접수를 별도로 확인해야 한다.
